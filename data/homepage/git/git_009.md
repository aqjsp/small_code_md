# Git实战项目

## 1 个人博客项目

### 1.1 项目概述
使用Git管理个人博客项目，实践从初始化到部署的完整流程。

### 1.2 项目步骤
1. **初始化项目**：
```bash
# 创建项目目录
mkdir personal-blog
cd personal-blog

# 初始化Git仓库
git init

# 创建基本文件结构
mkdir assets posts
touch index.html about.html
touch assets/style.css assets/script.js
touch README.md

# 创建.gitignore文件
echo ".DS_Store
node_modules
*.log" > .gitignore

# 初始提交
git add .
git commit -m "初始化个人博客项目"
```

2. **添加内容**：
```bash
# 添加博客文章
echo "# 我的第一篇博客

这是我的第一篇博客内容。

## 介绍

在这里我将分享我的学习和生活经验。" > posts/first-post.md

# 更新主页
echo "<!DOCTYPE html>
<html>
<head>
    <title>我的个人博客</title>
    <link rel=\"stylesheet\" href=\"assets/style.css\">
</head>
<body>
    <header>
        <h1>我的个人博客</h1>
    </header>
    <main>
        <section>
            <h2>最新文章</h2>
            <article>
                <h3>我的第一篇博客</h3>
                <p>这是我的第一篇博客内容。</p>
                <a href=\"posts/first-post.html\">阅读更多</a>
            </article>
        </section>
    </main>
    <footer>
        <p>&copy; 2023 我的个人博客</p>
    </footer>
</body>
</html>" > index.html

# 提交更改
git add .
git commit -m "添加第一篇博客文章和主页"
```

3. **创建功能分支**：
```bash
# 创建关于页面分支
git checkout -b feature/about-page

# 创建关于页面
echo "<!DOCTYPE html>
<html>
<head>
    <title>关于我 - 我的个人博客</title>
    <link rel=\"stylesheet\" href=\"assets/style.css\">
</head>
<body>
    <header>
        <h1>我的个人博客</h1>
        <nav>
            <a href=\"index.html\">首页</a>
            <a href=\"about.html\">关于我</a>
        </nav>
    </header>
    <main>
        <section>
            <h2>关于我</h2>
            <p>你好！我是一名热爱技术的博主，喜欢分享我的学习和工作经验。</p>
            <p>我的专业领域包括Web开发、数据分析和人工智能。</p>
        </section>
    </main>
    <footer>
        <p>&copy; 2023 我的个人博客</p>
    </footer>
</body>
</html>" > about.html

# 更新主页导航
sed -i.bak 's|</header>|    <nav>\n        <a href=\"index.html\">首页</a>\n        <a href=\"about.html\">关于我</a>\n    </nav>\n</header>|' index.html
rm index.html.bak

# 提交更改
git add .
git commit -m "添加关于页面和导航栏"
```

4. **合并功能分支**：
```bash
# 切换到主分支
git checkout main

# 合并功能分支
git merge --no-ff feature/about-page

# 删除功能分支
git branch -d feature/about-page

# 查看提交历史
git log --oneline --graph
```

5. **添加远程仓库**：
```bash
# 在GitHub上创建新仓库，然后添加远程仓库
git remote add origin https://github.com/username/personal-blog.git

# 推送到远程仓库
git push -u origin main
```

6. **部署到GitHub Pages**：
```bash
# 创建gh-pages分支
git checkout -b gh-pages

# 提交并推送
git push -u origin gh-pages

# 在GitHub仓库设置中启用GitHub Pages，选择gh-pages分支
```

### 1.3 学习目标
- 掌握Git仓库初始化和基本操作
- 理解分支的创建和合并
- 学会使用远程仓库进行协作
- 实践项目部署流程

## 3 开源贡献项目

### 3.1 项目概述
参与开源项目贡献，实践Git高级操作和开源协作流程。

### 3.2 项目步骤
1. **选择开源项目**：
- 在GitHub上找到感兴趣的开源项目
- 查看项目的贡献指南和代码规范

2. **Fork项目**：
- 在GitHub上Fork项目到个人账户
- 克隆Fork的仓库到本地

```bash
# 克隆Fork的仓库
git clone https://github.com/username/original-project.git
cd original-project

# 添加上游仓库
git remote add upstream https://github.com/original-owner/original-project.git

# 查看远程仓库
git remote -v
```

3. **创建功能分支**：
```bash
# 获取最新代码
git fetch upstream
git checkout main
git merge upstream/main

# 创建功能分支
git checkout -b fix/typo-in-readme
```

4. **修复问题**：
```bash
# 修复README中的拼写错误
sed -i.bak 's/accpet/accept/g' README.md
rm README.md.bak

# 提交更改
git add README.md
git commit -m "修复README中的拼写错误"
```

5. **推送并创建Pull Request**：
```bash
# 推送功能分支到Fork的仓库
git push -u origin fix/typo-in-readme

# 在GitHub上创建Pull Request
```

6. **处理反馈**：
- 根据项目维护者的反馈更新代码
- 使用rebase保持提交历史整洁

```bash
# 获取上游仓库的最新更改
git fetch upstream

# 变基功能分支到最新的main分支
git checkout fix/typo-in-readme
git rebase upstream/main

# 如果有冲突，解决冲突后继续
git rebase --continue

# 强制推送更新后的分支
git push origin fix/typo-in-readme --force-with-lease
```

### 3.3 学习目标
- 理解开源项目贡献流程
- 掌握Fork和Pull Request工作流
- 学会使用rebase保持提交历史整洁
- 实践与开源社区协作

2. **设置GitHub Actions**：
```bash
# 创建GitHub Actions工作流
mkdir -p .github/workflows

# 创建CI工作流
echo "name: CI/CD Pipeline

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  test:
    runs-on: ubuntu-latest
    
    strategy:
      matrix:
        node-version: [14.x, 16.x, 18.x]
    
    steps:
    - uses: actions/checkout@v3
    
    - name: 使用Node.js ${{ matrix.node-version }}
      uses: actions/setup-node@v3
      with:
        node-version: ${{ matrix.node-version }}
        cache: 'npm'
    
    - name: 安装依赖
      run: npm ci
    
    - name: 运行代码检查
      run: npm run lint
    
    - name: 运行测试
      run: npm test
    
    - name: 上传测试覆盖率
      uses: codecov/codecov-action@v3

  build:
    needs: test
    runs-on: ubuntu-latest
    
    steps:
    - uses: actions/checkout@v3
    
    - name: 使用Node.js
      uses: actions/setup-node@v3
      with:
        node-version: '18.x'
        cache: 'npm'
    
    - name: 安装依赖
      run: npm ci
    
    - name: 构建应用
      run: npm run build
    
    - name: 上传构建产物
      uses: actions/upload-artifact@v3
      with:
        name: dist
        path: dist/

  deploy:
    needs: build
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'
    
    steps:
    - uses: actions/checkout@v3
    
    - name: 下载构建产物
      uses: actions/download-artifact@v3
      with:
        name: dist
        path: dist/
    
    - name: 部署到GitHub Pages
      uses: peaceiris/actions-gh-pages@v3
      with:
        github_token: \${{ secrets.GITHUB_TOKEN }}
        publish_dir: ./dist" > .github/workflows/ci-cd.yml

# 提交CI配置
```

2. **创建提交前检查脚本**：
```bash

#!/bin/sh

# 检查代码风格
npm run lint
if [ $? -ne 0 ]; then
    echo "代码风格检查失败，请修复后再提交"
    exit 1
fi

npm test
if [ $? -ne 0 ]; then
    echo "测试失败，请修复后再提交"
    exit 1
fi

# 检查是否有大文件
MAX_FILE_SIZE=10485760  # 10MB
for file in $(git diff --cached --name-only); do
    size=$(git cat-file -s :$file)
    if [ $size -gt $MAX_FILE_SIZE ]; then
        echo "错误: 文件 $file 大小超过限制 ($size 字节)"
        exit 1
    fi
done

# 检查是否有敏感信息
for file in $(git diff --cached --name-only); do
    if git show :$file | grep -q "password\|secret\|token\|api_key"; then
        echo "错误: 文件 $file 可能包含敏感信息"

    fi
done

echo "预提交检查通过"
exit 0
EOF
```

```bash
    echo "错误: 请在main分支上执行发布"

# 检查是否有未提交的更改
if [ -n "$(git status --porcelain)" ]; then
    echo "错误: 有未提交的更改，请先提交或暂存"

# 获取版本号
read -p "请输入版本号 (例如: 1.0.0): " version

    echo "错误: 版本号格式不正确，应为 x.y.z"
    exit 1
fi

# 创建发布分支
git checkout -b release/v$version

# 更新版本号
echo "更新版本号到 $version"
# 这里根据项目类型更新版本号
# 例如: npm version $version --no-git-tag-version
```

### 7.2 项目步骤
1. **使用Git子模块**：
```bash
# 创建主项目

git add .gitmodules libs/
git commit -m "添加子模块"

# 克隆包含子模块的项目

# 更新子模块
git submodule update --remote

# 在子模块中工作
cd libs/shared-library
git checkout main
# 进行更改...
git commit -m "更新共享库"

# 在主项目中更新子模块引用
cd ../..
git add libs/shared-library
git commit -m "更新共享库到最新版本"
```

2. **使用Git subtree**：
```bash
# 创建主项目
mkdir main-project
cd main-project
git init

# 添加subtree
git subtree add --prefix=libs/shared-library https://github.com/example/shared-library.git main --squash

# 更新subtree
git subtree pull --prefix=libs/shared-library https://github.com/example/shared-library.git main --squash

# 推送subtree更改
git subtree push --prefix=libs/shared-library https://github.com/example/shared-library.git main

# 从subtree中提取更改
git subtree split --prefix=libs/shared-library --branch=shared-library-branch
git push https://github.com/example/shared-library.git shared-library-branch:main
```

3. **使用Repo工具管理多个仓库**：
```bash
# 安装Repo工具
# 下载repo脚本

chmod a+x repo

# 创建default.xml清单文件

           fetch="https://github.com/example/" />
  
  <default remote="origin"
           revision="main"
           sync-j="4" />
  
  <project name="app-main" path="app" />
  <project name="shared-library" path="libs/shared" />
  <project name="ui-components" path="libs/ui" />

git add default.xml
git commit -m "添加初始清单"

# 创建工作目录
mkdir workspace
cd workspace

# 初始化Repo
repo init -u https://github.com/example/manifest.git

# 同步所有仓库
repo sync

# 在所有仓库中创建分支
repo start new-feature --all

# 提交所有仓库的更改

# 推送所有分支
repo forall -c 'git push origin new-feature'
```

   ```bash

   # 列出所有工作树
   git worktree list
   
   # 删除工作树

   ```

2. **使用Git bisect查找问题**：二分查找定位问题提交
   ```bash

   # 标记当前提交为坏
   git bisect bad
   
   # 标记已知好的提交

   # Git会自动切换到中间提交，测试后标记好坏

   # 找到问题提交后结束

   ```

