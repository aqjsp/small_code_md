# Git高级操作

## 1 Git内部原理（对象、引用、包文件）

### 1.1 Git对象模型
Git是一个内容寻址文件系统，其核心是一个简单的键值对数据库（key-value data store）。你可以向数据库中插入任意类型的内容，它会返回一个键值，通过该键值可以在任意时刻再次检索该内容。

### 1.2 Git对象类型
1. **Blob对象**：存储文件的内容，不包含文件名、目录结构等信息
2. **Tree对象**：存储目录结构和Blob对象的关系，类似于操作系统的目录
3. **Commit对象**：存储提交信息、时间、作者、父提交等元数据
4. **Tag对象**：存储标签信息，通常用于标记特定的提交

### 1.3 查看Git对象
```bash
# 查看对象类型和内容
git cat-file -t <hash>    # 查看对象类型
git cat-file -p <hash>    # 查看对象内容

# 查看特定提交的树对象
git cat-file -p HEAD^{tree}

# 查看特定文件的内容
git cat-file -p HEAD:filename.txt
```

### 1.4 Git引用（References）
引用是指向提交的指针，允许Git使用符号名称而不是SHA-1哈希值来引用提交。

1. **HEAD引用**：指向当前分支的最新提交
2. **分支引用**：存储在`.git/refs/heads/`目录下
3. **远程引用**：存储在`.git/refs/remotes/`目录下
4. **标签引用**：存储在`.git/refs/tags/`目录下

```bash
# 查看引用
git show-ref

# 查看特定引用
git show-ref heads/main

# 查看HEAD引用
git symbolic-ref HEAD

# 直接查看引用文件
cat .git/refs/heads/main
```

### 1.5 包文件（Packfiles）
为了节省空间和提高效率，Git会将对象存储在包文件中。

```bash
# 手动触发打包
git gc

# 查看包文件信息
git verify-pack -v .git/objects/pack/pack-*.idx

# 查看松散对象
git count-objects -v
```

### 1.6 Git索引（Index）
索引是Git的暂存区，它是一个二进制文件，存储在`.git/index`中。

```bash
# 查看索引内容
git ls-files --stage

# 查看索引状态
git status --porcelain
```

## 2 高级合并策略

### 2.1 合并策略类型
1. **递归合并（Recursive）**：默认的双分支合并策略
2. **解析合并（Resolve）**：简单的双分支合并策略
3. **八爪鱼合并（Octopus）**：多分支合并策略
4. **我们的合并（Ours）**：保留当前分支的版本
5. **子树合并（Subtree）**：用于子树合并

### 2.2 选择合并策略
```bash
# 使用特定策略合并
git merge -s recursive branchname
git merge -s octopus branch1 branch2
git merge -s ours branchname
git merge -s subtree branchname
```

### 2.3 递归合并选项
```bash
# 忽略空白差异
git merge -Xignore-space-change branchname

# 忽略所有空白差异
git merge -Xignore-all-space branchname

# 忽略换行符差异
git merge -Xignore-space-at-eol branchname

# 重命名检测
git merge -Xrename-threshold=50 branchname

# 算法选择
git merge -Xpatience branchname
git merge -Xhistogram branchname
```

### 2.4 合并驱动
```bash
# 查看合并驱动配置
git config --get merge.driver

# 设置自定义合并驱动
git config merge.custom.driver 'custom-merge %O %A %B %L'
git config merge.custom.name 'Custom merge driver'
```

### 2.5 合并冲突的高级处理
```bash
# 查看冲突文件的基版本、当前版本和其他版本
git show :1:file.txt    # 基版本
git show :2:file.txt    # 当前版本
git show :3:file.txt    # 其他版本

# 使用合并工具解决冲突
git mergetool

# 手动解决冲突后标记为已解决
git add file.txt

# 继续合并
git commit
```

### 2.6 cherry-pick
```bash
# 将特定提交应用到当前分支
git cherry-pick commit_hash

# 应用多个提交
git cherry-pick commit1..commit2

# 应用提交但不提交
git cherry-pick --no-commit commit_hash

# 应用提交并保留原提交信息
git cherry-pick -x commit_hash

# 交互式选择提交
git cherry-pick -i commit_hash
```

## 3 子模块与子树

### 3.1 Git子模块（Submodules）
子模块允许你将一个Git仓库作为另一个Git仓库的子目录。

#### 3.1.1 添加子模块
```bash
# 添加子模块
git submodule add https://github.com/user/repository.git path/to/submodule

# 添加特定分支的子模块
git submodule add -b develop https://github.com/user/repository.git path/to/submodule

# 添加特定提交的子模块
git submodule add https://github.com/user/repository.git path/to/submodule
cd path/to/submodule
git checkout commit_hash
```

#### 3.1.2 克隆包含子模块的项目
```bash
# 克隆项目并初始化子模块
git clone --recursive https://github.com/user/project.git

# 或者分两步
git clone https://github.com/user/project.git
cd project
git submodule init
git submodule update
```

#### 3.1.3 更新子模块
```bash
# 更新所有子模块到最新提交
git submodule update --remote

# 更新特定子模块
git submodule update --remote path/to/submodule

# 更新子模块到指定提交
cd path/to/submodule
git checkout commit_hash
cd ../..
git add path/to/submodule
git commit -m "Update submodule to specific commit"
```

#### 3.1.4 子模块常用命令
```bash
# 查看子模块状态
git submodule status

# 初始化子模块
git submodule init

# 更新子模块
git submodule update

# 同步子模块URL
git submodule sync

# 删除子模块
git submodule deinit path/to/submodule
git rm path/to/submodule
```

### 3.2 Git子树（Subtree）
子树合并是一种将另一个仓库的代码合并到当前仓库的方法，与子模块不同，子树会将代码直接合并到主仓库中。

#### 3.2.1 添加子树
```bash
# 添加远程仓库
git remote add subtree-origin https://github.com/user/repository.git

# 获取远程仓库内容
git fetch subtree-origin

# 合并子树
git merge -s ours --no-commit subtree-origin/main
git read-tree --prefix=path/to/subtree/ -u subtree-origin/main
git commit -m "Add subtree"
```

#### 3.2.2 更新子树
```bash
# 获取远程仓库更新
git fetch subtree-origin

# 合并更新
git merge -s subtree subtree-origin/main
```

#### 3.2.3 子树与子模块的比较
| 特性 | 子模块 | 子树 |
|------|--------|------|
| 存储方式 | 独立仓库 | 合并到主仓库 |
| 版本控制 | 独立版本 | 与主仓库同步 |
| 克隆复杂度 | 需要额外步骤 | 一次性克隆 |
| 更新方式 | 独立更新 | 合并更新 |
| 贡献流程 | 复杂 | 简单 |

## 4 钩子与自定义Git

### 4.1 Git钩子（Hooks）
钩子是在Git执行特定事件（如提交、推送、接收推送等）前后自动运行的脚本。

#### 4.1.1 钩子类型
1. **客户端钩子**：
   - `pre-commit`：在运行`git commit`前执行
   - `prepare-commit-msg`：在提交信息编辑器启动前执行
   - `commit-msg`：在提交信息编辑完成后执行
   - `post-commit`：在提交完成后执行
   - `pre-push`：在运行`git push`前执行
   - `pre-rebase`：在变基前执行

2. **服务端钩子**：
   - `pre-receive`：在接收推送前执行
   - `post-receive`：在接收推送完成后执行
   - `update`：在更新每个分支前执行

#### 4.1.2 钩子示例
```bash
# .git/hooks/pre-commit
#!/bin/sh
# 运行代码格式检查
npm run lint
if [ $? -ne 0 ]; then
  echo "代码格式检查失败，请修复后重试"
  exit 1
fi

# .git/hooks/commit-msg
#!/bin/sh
# 检查提交信息格式
commit_regex='^(feat|fix|docs|style|refactor|test|chore)(\(.+\))?: .{1,50}'
if ! grep -qE "$commit_regex" "$1"; then
  echo "提交信息格式不正确，请遵循规范"
  exit 1
fi
```

#### 4.1.3 启用钩子
```bash
# 复制示例钩子文件
cp .git/hooks/pre-commit.sample .git/hooks/pre-commit

# 设置执行权限
chmod +x .git/hooks/pre-commit
```

## 5 性能优化与维护

### 5.1 Git性能优化
1. **索引优化**：
   ```bash
   # 更新索引信息
   git update-index --refresh
   ```

2. **打包优化**：
   ```bash
   # 手动触发垃圾回收
   git gc --aggressive
   ```

3. **浅克隆优化**：
   ```bash
   # 只克隆最新提交
   git clone --depth 1 https://github.com/user/repository.git
   
   # 部分克隆
   git clone --filter=blob:none https://github.com/user/repository.git
   ```

4. **大文件处理**：
   ```bash
   # 使用Git LFS
   git lfs install
   git lfs track "*.zip"
   git add .gitattributes
   git commit -m "Track zip files with LFS"
   ```

### 5.2 Git维护
1. **检查仓库完整性**：
   ```bash
   # 检查对象完整性
   git fsck
   
   # 检查丢失的对象
   git fsck --lost-found
   ```

2. **清理仓库**：
   ```bash
   # 清理不必要的文件和优化本地仓库
   git gc
   
   # 清理远程引用
   git remote prune origin
   
   # 清理reflog
   git reflog expire --expire=now --all
   git gc --prune=now
   ```

3. **修复损坏的仓库**：
   ```bash
   # 重置索引
   git reset
   
   # 重建索引
   git read-tree --empty
   git read-tree HEAD
   ```

### 5.3 Git性能监控
```bash
# 查看仓库统计信息
git count-objects -v

# 查看打包文件信息
git verify-pack -v .git/objects/pack/*.idx

# 查找大文件

```

### 5.4 Git历史优化
```bash
# 重写历史（谨慎使用）

# 使用BFG Repo-Cleaner（更安全）

```

## 8 Git高级工作流

### 8.1 Git Flow工作流
Git Flow是一种严格的分支模型，适合大型项目和版本发布。

```bash
# 安装git-flow
# macOS
brew install git-flow-avh
# Ubuntu/Debian
apt-get install git-flow

# 初始化Git Flow
git flow init

# 创建功能分支
git flow feature start new-feature

# 完成功能分支
git flow feature finish new-feature

# 创建发布分支
git flow release start v1.0.0

# 完成发布分支
git flow release finish v1.0.0

# 创建热修复分支
git flow hotfix start critical-bug

# 完成热修复分支
git flow hotfix finish critical-bug
```

### 8.2 GitHub Flow工作流
GitHub Flow是一种简单的工作流，适合持续部署的项目。

```bash
# 创建功能分支
git checkout -b new-feature

# 提交更改
git commit -m "Add new feature"

# 推送分支
git push origin new-feature

# 创建Pull Request
# 在GitHub上创建PR，请求合并到main分支

# 合并PR
# 经过代码审查后，合并到main分支

# 部署
# 自动部署main分支的更改
```

### 8.3 GitLab Flow工作流
GitLab Flow结合了Git Flow和GitHub Flow的优点。

```bash
# 创建功能分支
git checkout -b feature/new-feature

# 提交更改
git commit -m "Add new feature"

# 推送分支
git push origin feature/new-feature

# 创建合并请求
# 在GitLab上创建MR，请求合并到develop分支

# 合并到develop分支
# 经过代码审查后，合并到develop分支

# 创建发布分支
git checkout -b release/v1.0.0 develop

# 完成发布
git checkout main
git merge --no-ff release/v1.0.0
git tag -a v1.0.0 -m "Release version 1.0.0"
git checkout develop
git merge --no-ff release/v1.0.0
```

### 8.4 Trunk Based Development工作流
Trunk Based Development是一种基于主干的开发模式，适合快速迭代。

```bash
# 直接在主分支上开发小型功能
git checkout main
# 开发功能...
git commit -m "Add small feature"

# 使用短期功能分支开发大型功能
git checkout -b feature-large
# 开发功能...
git commit -m "Add part of large feature"
# 合并回主分支
git checkout main
git merge --no-ff feature-large
git branch -d feature-large

# 使用特性开关控制功能发布
# 在代码中使用特性开关控制新功能的启用
```

## 9 Git高级故障排除

### 9.1 解决常见问题
```bash
# 解决"fatal: Not a git repository"错误
git init

# 解决"fatal: Couldn't find remote ref refs/heads/master"
git remote update origin --prune

# 解决"error: The following untracked working tree files would be overwritten by checkout"
git clean -fd

# 解决"fatal: refusing to merge unrelated histories"
git pull --allow-unrelated-histories

# 解决"error: Your local changes to the following files would be overwritten by merge"
git stash
git pull
git stash pop
```

### 9.2 恢复丢失的提交
```bash
# 使用reflog查找丢失的提交
git reflog

# 恢复丢失的提交
git reset --hard COMMIT_ID

# 创建新分支指向丢失的提交
git branch recovery-branch COMMIT_ID

# 使用fsck查找悬空提交
git fsck --lost-found
# 查看悬空提交
git log .git/lost-found/commit/*
```

### 9.3 修复损坏的仓库
```bash
# 检查仓库完整性
git fsck --full

# 重置HEAD到已知良好状态
git update-ref HEAD HEAD

# 重建索引
git read-tree --empty
git read-tree HEAD

# 重新打包对象
git repack -a -d

# 清理并重建仓库
git gc --prune=now --aggressive
```

### 9.4 处理大文件问题
```bash
# 查找大文件
git rev-list --objects --all | git cat-file --batch-check='%(objecttype) %(objectname) %(objectsize) %(rest)' | sed -n 's/^blob //p' | sort --numeric-sort --key=2 | tail -10

# 使用Git LFS跟踪大文件
git lfs install
git lfs track "*.zip"
git add .gitattributes
git commit -m "Track zip files with LFS"

# 从历史中移除大文件
git filter-branch --force --index-filter 'git rm --cached --ignore-unmatch large-file.zip' --prune-empty --tag-name-filter cat -- --all

# 使用BFG Repo-Cleaner（更安全）
java -jar bfg.jar --strip-blobs-bigger-than 100M my-repo.git
```
