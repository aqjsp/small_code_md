# Git进阶主题

## 1 Git内部原理

### 1.1 Git对象模型
Git是一个内容寻址文件系统，其核心是一个简单的键值对数据库(key-value data store)。

#### 对象类型
1. **Blob对象**：存储文件内容
2. **Tree对象**：存储目录结构和文件名
3. **Commit对象**：存储提交信息、时间戳、作者等
4. **Tag对象**：存储标签信息

#### 查看Git对象
```bash
# 查看Git对象
git cat-file -p <hash>

# 查看对象类型
git cat-file -t <hash>

# 查看对象大小
git cat-file -s <hash>

# 查看所有对象
git cat-file --batch-check --batch-all-objects
```

#### 对象存储原理
```bash
# 查看Git对象存储目录
find .git/objects -type f

# 查看对象内容
git cat-file -p $(git rev-parse HEAD:README.md)

# 手动创建对象
echo "test content" | git hash-object -w --stdin
```

### 1.2 引用和符号引用
Git中的引用(Refs)是指向提交的指针，使Git能够理解分支、标签等概念。

#### 引用类型
1. **HEAD**：当前工作分支的符号引用
2. **分支引用**：指向分支最新提交
3. **远程引用**：指向远程仓库分支
4. **标签引用**：指向特定提交

#### 查看引用
```bash
# 查看所有引用
git show-ref

# 查看HEAD引用
git symbolic-ref HEAD

# 查看分支引用
git show-ref heads

# 查看远程引用
git show-ref remotes

# 查看标签引用
git show-ref tags
```

#### 引用文件位置
```bash
# 查看引用文件
cat .git/HEAD
cat .git/refs/heads/main
cat .git/refs/remotes/origin/main
cat .git/refs/tags/v1.0
```

### 1.3 包文件和垃圾回收
为了节省空间和提高效率，Git会将松散对象打包成包文件(packfiles)。

#### 手动触发垃圾回收
```bash
# 执行垃圾回收
git gc

# 激进的垃圾回收
git gc --aggressive

# 查看包文件
ls -la .git/objects/pack/
```

#### 查看包文件信息
```bash
# 查看包文件内容
git verify-pack -v .git/objects/pack/pack-*.idx

# 查看包文件统计
git count-objects -v
```

### 1.4 引用规格
引用规格(refspecs)控制远程仓库和本地仓库之间的引用映射。

#### 查看引用规格
```bash
# 查看远程仓库的引用规格
git remote show origin

# 查看配置文件中的引用规格
git config --get-all remote.origin.fetch
```

#### 自定义引用规格
```bash
# 添加引用规格
git config remote.origin.fetch "+refs/heads/*:refs/remotes/origin/*"

# 只获取特定分支
git config remote.origin.fetch "+refs/heads/main:refs/remotes/origin/main"

# 获取所有标签
git config remote.origin.fetch "+refs/tags/*:refs/tags/*"
```

### 1.5 传输协议
Git支持多种传输协议：本地协议、HTTP/HTTPS协议、SSH协议和Git协议。

#### 本地协议
```bash
# 克隆本地仓库
git clone /path/to/repo
git clone file:///path/to/repo
```

#### HTTP/HTTPS协议
```bash
# 通过HTTPS克隆
git clone https://github.com/user/repo.git

# 智能HTTP协议
git clone https://git.example.com/repo.git
```

#### SSH协议
```bash
# 通过SSH克隆
git clone git@github.com:user/repo.git

# 使用自定义SSH端口
git clone ssh://git@github.com:7999/user/repo.git
```

#### Git协议
```bash
# 通过Git协议克隆
git clone git://github.com/user/repo.git
```

## 3 Git子模块与子树

### 3.1 Git子模块
子模块允许将一个Git仓库作为另一个Git仓库的子目录。

#### 添加子模块
```bash
# 添加子模块
git submodule add https://github.com/user/repo.git path/to/submodule

# 添加特定分支的子模块
git submodule add -b develop https://github.com/user/repo.git path/to/submodule

# 添加子模块但不检出
git submodule add --no-checkout https://github.com/user/repo.git path/to/submodule
```

#### 克隆包含子模块的项目
```bash
# 克隆项目并初始化子模块
git clone --recurse-submodules https://github.com/user/project.git

# 或者分两步
git clone https://github.com/user/project.git
cd project
git submodule init
git submodule update
```

#### 管理子模块
```bash
# 查看子模块状态
git submodule status

# 更新子模块到最新提交
git submodule update --remote

# 更新所有子模块
git submodule update --init --recursive

# 拉取子模块最新更改
git submodule foreach git pull origin main
```

#### 在子模块中工作
```bash
# 进入子模块目录
cd path/to/submodule

# 在子模块中工作
git checkout main
git pull
# 做出更改...

# 返回主项目并提交子模块更新
cd ../..
git add path/to/submodule
git commit -m "更新子模块"
```

#### 删除子模块
```bash
# 删除子模块
git submodule deinit path/to/submodule
git rm path/to/submodule
git commit -m "删除子模块"

# 清理.git/modules中的子模块数据
rm -rf .git/modules/path/to/submodule
```

### 3.2 Git子树合并
子树合并是另一种包含外部项目的方式，它将外部项目的历史合并到主项目中。

#### 添加子树
```bash
# 添加远程仓库
git remote add -f subtree_repo https://github.com/user/repo.git

# 合并子树
git merge -s ours --no-commit subtree_repo/main
git read-tree --prefix=path/to/subtree/ -u subtree_repo/main
git commit -m "添加子树"

# 或者使用git subtree命令
git subtree add --prefix=path/to/subtree https://github.com/user/repo.git main
```

#### 更新子树
```bash
# 从远程仓库拉取更新
git fetch subtree_repo main
git merge -s subtree subtree_repo/main

# 或者使用git subtree命令
git subtree pull --prefix=path/to/subtree https://github.com/user/repo.git main
```

#### 推送子树更改
```bash
# 推送子树更改到原始仓库
git subtree push --prefix=path/to/subtree https://github.com/user/repo.git main

# 或者先推送到主项目，再推送到子树项目
git push origin main
git subtree split --prefix=path/to/subtree --annotate="(split)" main
git push https://github.com/user/repo.git main
```

## 4 Git钩子

### 4.1 钩子类型
Git钩子是在特定事件发生时自动执行的脚本，分为客户端钩子和服务器端钩子。

#### 客户端钩子
1. **提交工作流钩子**：pre-commit、prepare-commit-msg、commit-msg、post-commit
2. **电子邮件工作流钩子**：applypatch-msg、pre-applypatch、post-applypatch
3. **其他钩子**：pre-rebase、post-rewrite、post-checkout、post-merge、pre-push

#### 服务器端钩子
1. **pre-receive**：处理推送操作前
2. **post-receive**：处理推送操作后
3. **update**：更新每个引用前

### 4.2 常用钩子示例

#### pre-commit钩子
```bash
#!/bin/sh
# .git/hooks/pre-commit

# 运行代码检查
npm run lint
if [ $? -ne 0 ]; then
    echo "代码检查失败，请修复后再提交"
    exit 1
fi

# 运行测试
npm test
if [ $? -ne 0 ]; then
    echo "测试失败，请修复后再提交"
    exit 1
fi

# 检查文件大小
for file in $(git diff --cached --name-only); do
    if [ -f "$file" ]; then
        size=$(stat -c%s "$file")
        if [ $size -gt 1048576 ]; then
            echo "文件 $file 大小超过1MB，请检查"
            exit 1
        fi
    fi
done

exit 0
```

#### commit-msg钩子
```bash
#!/bin/sh
# .git/hooks/commit-msg

# 检查提交信息格式
commit_regex='^(feat|fix|docs|style|refactor|test|chore)(\(.+\))?: .{1,50}'

if ! grep -qE "$commit_regex" "$1"; then
    echo "提交信息格式不正确，请使用以下格式："
    echo "feat: 添加新功能"
    echo "fix: 修复bug"
    echo "docs: 更新文档"
    echo "..."
    exit 1
fi

exit 0
```

#### pre-push钩子
```bash
#!/bin/sh
# .git/hooks/pre-push

# 运行完整测试套件
npm run test:full
if [ $? -ne 0 ]; then
    echo "完整测试失败，请修复后再推送"
    exit 1
fi

# 检查分支名称
current_branch=$(git symbolic-ref HEAD | sed -e 's,.*/\(.*\),\1,')
if [ "$current_branch" = "main" ]; then
    echo "不能直接推送到main分支，请创建功能分支"
    exit 1
fi

exit 0
```

#### post-receive钩子
```bash
#!/bin/sh
# .git/hooks/post-receive

# 部署到生产环境
while read oldrev newrev refname; do
    if [ "$refname" = "refs/heads/main" ]; then
        echo "部署main分支到生产环境..."
        cd /path/to/production
        git pull origin main
        npm install
        npm run build
        systemctl reload nginx
        echo "部署完成"
    fi
done
```

### 4.3 钩子管理
```bash
# 启用钩子
chmod +x .git/hooks/pre-commit

# 禁用钩子
chmod -x .git/hooks/pre-commit

# 全局钩子目录
git config --global core.hooksPath /path/to/global/hooks
```

## 5 Git扩展工具

### 5.1 Git大型文件存储(LFS)
Git LFS是Git的扩展，用于处理大文件。

#### 安装和设置
```bash
# 安装Git LFS
git lfs install

# 跟踪大文件
git lfs track "*.psd"
git lfs track "*.zip"
git lfs track "*.mov"

# 查看跟踪的文件类型
git lfs track

# 提交.gitattributes文件
git add .gitattributes
git commit -m "配置Git LFS"
```

#### 使用Git LFS
```bash
# 添加大文件
git add large-file.zip
git commit -m "添加大文件"

# 推送到远程仓库
git push origin main

# 克隆包含LFS文件的仓库
git clone https://github.com/user/repo.git
cd repo
git lfs pull
```

### 5.2 Git-Crypt
Git-Crypt用于加密Git仓库中的敏感文件。

#### 初始化Git-Crypt
```bash
# 初始化Git-Crypt
git-crypt init

# 生成GPG密钥（如果还没有）
gpg --gen-key

# 添加用户
git-crypt add-gpg-user user@example.com

# 配置加密文件
echo "secrets/* filter=git-crypt diff=git-crypt" >> .gitattributes
echo "*.key filter=git-crypt diff=git-crypt" >> .gitattributes

# 提交配置
git add .gitattributes
git commit -m "配置Git-Crypt"
```

#### 使用Git-Crypt
```bash
# 添加敏感文件
echo "password=secret123" > secrets/config.txt
git add secrets/config.txt
git commit -m "添加敏感配置"

# 解密文件（查看内容）
git-crypt export-key git-crypt-key
git-crypt unlock git-crypt-key

# 加密文件
git-crypt lock
```

### 5.3 Git-Annex
Git-Annex用于管理大文件而不将其存储在Git仓库中。

#### 初始化Git-Annex
```bash
# 初始化Git-Annex
git init
git annex init "my repository"

# 添加大文件
git annex add large-file.mp4
git commit -m "添加大文件"

# 查看文件状态
git annex status
```

#### 使用Git-Annex
```bash
# 获取文件内容
git annex get large-file.mp4

# 释放文件内容（保留链接）
git annex drop large-file.mp4

# 同步到远程仓库
git annex sync origin

# 查看文件位置
git annex whereis large-file.mp4
```

## 6 Git性能优化

### 6.1 仓库性能优化
```bash
# 打包松散对象
git gc

# 激进的垃圾回收
git gc --aggressive

# 重新打包仓库
git repack -a -d --depth=250 --window=250

# 清理无用的引用
git remote prune origin

# 清理reflog
git reflog expire --expire=now --all
git gc --prune=now
```

### 6.2 网络性能优化
```bash
# 浅克隆（只获取最新提交）
git clone --depth 1 https://github.com/user/repo.git

# 部分克隆（只获取需要的文件）
git clone --filter=blob:none https://github.com/user/repo.git

# 稀疏检出（只检出需要的目录）
git clone --no-checkout https://github.com/user/repo.git
cd repo
git sparse-checkout init --cone
git sparse-checkout set dir1 dir2
git checkout

# 使用协议版本2
git config --global protocol.version 2
```

### 6.3 大文件处理
```bash
# 查找大文件
git rev-list --objects --all | git cat-file --batch-check='%(objecttype) %(objectname) %(objectsize) %(rest)' | sed -n 's/^blob //p' | sort --numeric-sort --key=2 | tail -10

# 使用BFG删除大文件
java -jar bfg.jar --strip-blobs-bigger-than 100M

# 使用filter-branch删除大文件
git filter-branch --force --index-filter 'git rm --cached --ignore-unmatch large-file.zip' --prune-empty --tag-name-filter cat -- --all
```

## 9 Git高级工作流

### 9.1 Git Flow工作流
Git Flow是一种流行的分支模型，适用于有计划发布周期的项目。

#### 安装和设置
```bash
# 安装git-flow（Linux）
sudo apt-get install git-flow

# 安装git-flow（Mac）
brew install git-flow-avh

# 安装git-flow（Windows）
# 下载并安装git-flow-avh Windows安装包
```

#### Git Flow基本操作
```bash
# 初始化Git Flow
git flow init

# 创建功能分支
git flow feature start new-feature
# 在功能分支上工作...
git flow feature finish new-feature

# 创建发布分支
git flow release start v1.0.0
# 在发布分支上修复bug...
git flow release finish v1.0.0

# 创建热修复分支
git flow hotfix start critical-fix
# 修复紧急问题...
git flow hotfix finish critical-fix
```

### 9.2 GitHub Flow工作流
GitHub Flow是一种简单的工作流，适用于持续部署的项目。

#### GitHub Flow基本操作
```bash
# 1. 创建分支
git checkout -b new-feature

# 2. 提交更改
git add .
git commit -m "添加新功能"

# 3. 推送分支
git push origin new-feature

# 4. 创建Pull Request
# 在GitHub网站上创建Pull Request

# 5. 代码审查和合并
# 代码审查通过后，合并到main分支

# 6. 部署
# main分支自动部署到生产环境
```

### 9.3 GitLab Flow工作流
GitLab Flow结合了Git Flow和GitHub Flow的优点。

#### GitLab Flow基本操作
```bash
# 1. 创建功能分支
git checkout -b feature/new-feature

# 2. 提交更改
git add .
git commit -m "添加新功能"

# 3. 推送分支
git push origin feature/new-feature

# 4. 创建合并请求
# 在GitLab网站上创建合并请求

# 5. 合并到开发分支
git checkout develop
git merge feature/new-feature

# 6. 创建发布分支
git checkout -b release/v1.0.0

# 7. 测试和修复
# 在发布分支上进行测试和修复

# 8. 合并到主分支
git checkout main
git merge release/v1.0.0

# 9. 打标签
git tag v1.0.0
git push origin v1.0.0
```

## 10 Git与DevOps集成

### 10.1 Git与CI/CD集成

#### GitHub Actions示例
```yaml
# .github/workflows/ci.yml
name: CI/CD Pipeline

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main ]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v2
    
    - name: Set up Node.js
      uses: actions/setup-node@v2
      with:
        node-version: '14'
        
    - name: Install dependencies
      run: npm install
      
    - name: Run tests
      run: npm test
      
    - name: Run linting
      run: npm run lint
      
  build:
    needs: test
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v2
    
    - name: Set up Node.js
      uses: actions/setup-node@v2
      with:
        node-version: '14'
        
    - name: Install dependencies
      run: npm install
      
    - name: Build application
      run: npm run build
      
    - name: Upload build artifacts
      uses: actions/upload-artifact@v2
      with:
        name: build-files
        path: dist/
        
  deploy:
    needs: build
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'
    steps:
    - name: Download build artifacts
      uses: actions/download-artifact@v2
      with:
        name: build-files
        path: dist/
        
    - name: Deploy to production
      run: |
        # 部署脚本
        echo "部署到生产环境"
```
