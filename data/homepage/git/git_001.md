# Git 基础入门

## 1 什么是版本控制系统

### 1.1 版本控制系统的定义
版本控制系统（Version Control System，简称VCS）是一种记录文件内容变化，以便将来查阅特定版本修订情况的系统。它能够追踪和记录文件的每一次修改，包括谁在何时、为何做了何种修改。

### 1.2 为什么需要版本控制系统
1. **备份与恢复**：自动保存文件的历史版本，防止数据丢失
2. **协作开发**：多人同时工作时，可以合并各自的工作成果
3. **版本追踪**：可以查看文件的历史变化，了解每个版本的修改内容
4. **分支管理**：可以创建多个开发线，并行开发不同功能
5. **错误回滚**：当出现问题时，可以快速回退到之前的稳定版本

### 1.3 版本控制系统的类型
1. **本地版本控制系统**：如RCS，只在本地计算机上保存文件的各个版本
2. **集中式版本控制系统**：如CVS、SVN，有一个中央服务器保存所有版本
3. **分布式版本控制系统**：如Git、Mercurial，每个客户端都保存完整的代码仓库副本

## 2 Git与其他版本控制系统的区别

### 2.1 Git与SVN的主要区别

| 特性 | Git | SVN |
|------|-----|-----|
| 架构 | 分布式 | 集中式 |
| 分支 | 轻量级，快速 | 重量级，缓慢 |
| 存储 | 快照 | 文件差异 |
| 离线工作 | 支持 | 不支持 |
| 合并 | 强大 | 复杂 |
| 学习曲线 | 较陡 | 相对平缓 |

### 2.2 Git的优势
1. **分布式架构**：每个开发者都有完整的代码仓库，可以离线工作
2. **强大的分支管理**：创建和合并分支非常快速和简单
3. **高效的数据存储**：使用快照方式存储数据，处理大文件更高效
4. **完整的历史记录**：可以查看完整的开发历史和文件变化
5. **灵活的工作流**：支持多种工作流程，适应不同团队需求

### 2.3 Git的适用场景
- 开源项目开发
- 大型团队协作
- 频繁的分支和合并操作
- 需要离线工作的场景
- 对性能要求高的项目

## 3 Git的安装与配置

### 3.1 Windows系统安装Git
1. 访问Git官网：https://git-scm.com/
2. 下载Windows版本的Git安装程序
3. 运行安装程序，按照提示完成安装
4. 安装完成后，可以在开始菜单中找到Git Bash、Git GUI等工具

### 3.2 Linux系统安装Git
```bash
# Ubuntu/Debian
sudo apt-get update
sudo apt-get install git

# CentOS/RHEL
sudo yum install git

# Fedora
sudo dnf install git
```

### 3.3 macOS系统安装Git
```bash
# 使用Homebrew安装
brew install git

# 或者从官网下载安装程序
```

### 3.4 Git基本配置
安装完成后，需要进行基本配置：

```bash
# 设置用户名（将显示在提交记录中）
git config --global user.name "你的名字"

# 设置邮箱（将显示在提交记录中）
git config --global user.email "your.email@example.com"

# 设置默认编辑器
git config --global core.editor "vim"  # 或者 "notepad"（Windows）

# 设置默认分支名（Git 2.28+）
git config --global init.defaultBranch main

# 查看所有配置
git config --list

# 查看特定配置
git config user.name
```

### 3.5 Git配置文件位置
- **系统级配置**：`/etc/gitconfig`（Windows系统在Git安装目录下）
- **用户级配置**：`~/.gitconfig`或`~/.config/git/config`
- **项目级配置**：`.git/config`

配置的优先级：项目级 > 用户级 > 系统级

## 4 Git基本概念

### 4.1 仓库（Repository）
仓库是Git用于管理代码的地方，包含了所有的代码版本历史。仓库分为：
- **本地仓库**：存储在本地计算机上的仓库
- **远程仓库**：存储在远程服务器上的仓库（如GitHub、GitLab）

### 4.2 工作区（Working Directory）
工作区是你在电脑上看到的目录，是你当前工作的区域。你可以在这里修改、添加、删除文件。

### 4.3 暂存区（Staging Area）
暂存区（也称为索引）是临时存放你的改动的地方，实际上是一个文件，保存即将提交的文件列表信息。暂存区让你能够精确控制哪些改动会被提交。

### 4.4 提交（Commit）
提交是将暂存区的文件改动提交到仓库中，生成一个新的版本。每次提交都会生成一个唯一的哈希值（SHA-1），作为这次提交的ID。

### 4.5 HEAD指针
HEAD是一个指针，指向当前分支的最新提交。当你切换分支或创建新提交时，HEAD会相应地移动。

### 4.6 Git对象的类型
1. **Blob对象**：存储文件的内容
2. **Tree对象**：存储目录结构和Blob对象的关系
3. **Commit对象**：存储提交信息、时间、作者、父提交等
4. **Tag对象**：存储标签信息，通常用于标记特定的提交

## 5 Git的基本工作流程

### 5.1 Git工作流程图
```
工作区 → git add → 暂存区 → git commit → 本地仓库 → git push → 远程仓库
   ↑                                        ↓
   ← git checkout ← 本地仓库 ← git pull ← 远程仓库
```

### 5.2 基本工作流程步骤

1. **在工作区中修改文件**
   - 编辑现有文件
   - 创建新文件
   - 删除不需要的文件

2. **查看文件状态**
   ```bash
   git status
   ```
   这个命令会显示工作区和暂存区的状态，包括：
   - 未跟踪的文件（Untracked files）
   - 已修改但未暂存的文件（Changes not staged for commit）
   - 已暂存待提交的文件（Changes to be committed）

3. **将修改添加到暂存区**
   ```bash
   # 添加特定文件
   git add filename
   
   # 添加所有修改的文件
   git add .
   
   # 添加特定类型的文件
   git add *.txt
   ```

4. **提交暂存区的修改**
   ```bash
   git commit -m "提交说明"
   ```
   提交说明应该清晰明了，描述这次提交的目的和内容。

5. **推送到远程仓库（可选）**
   ```bash
   git push origin main
   ```

6. **从远程仓库拉取最新代码（可选）**
   ```bash
   git pull origin main
   ```

### 5.3 Git文件状态的生命周期
```
未跟踪 → 已修改 → 已暂存 → 已提交
   ↑        ↓        ↓        ↓
   ← git add ← git add ← git commit
```

### 5.4 实际示例
假设我们要创建一个简单的项目并提交到Git仓库：

```bash
# 1. 创建项目目录
mkdir myproject
cd myproject

# 2. 初始化Git仓库
git init

# 3. 创建一个README文件
echo "# My Project" > README.md

# 4. 查看状态
git status
# 输出：Untracked files: README.md

# 5. 添加文件到暂存区
git add README.md

# 6. 再次查看状态
git status
# 输出：Changes to be committed: new file: README.md

# 7. 提交文件
git commit -m "Add initial README file"

# 8. 查看提交历史
git log --oneline
```

### 5.5 Git基本命令总结
- `git init`：初始化一个新的Git仓库
- `git clone`：克隆一个远程仓库到本地
- `git status`：查看工作区和暂存区的状态
- `git add`：将文件添加到暂存区
- `git commit`：提交暂存区的修改到本地仓库
- `git push`：将本地仓库的修改推送到远程仓库
- `git pull`：从远程仓库拉取最新代码并合并
- `git log`：查看提交历史
- `git diff`：查看文件差异
